# Search the China trademark classification

Type what you sell and see where it sits in the classification CNIPA examines against — all **32,665 goods and services items**, in English and in the official Chinese wording.

<div id="tm-search" data-index="../data/search-index.json"></div>

## How to read a result

| Column | What it is | Why it matters |
|---|---|---|
| **Class** | One of the 45 Nice classes, in the Chinese numbering (01–45) | Fees, examination and protection all run per class |
| **Item** | The official Chinese wording, with its English name above it and the catalogue code where CNIPA assigns one | The Chinese text is what appears on your application — the English is a reference, not the filing |
| **Sub-class** | The 类似群, e.g. `4209` | Items in the same class but different sub-classes are generally **not** similar goods |

## Why the sub-class decides your filing

Foreign applicants usually treat a class as one bucket and pick ten familiar-sounding items. In China that can leave most of the class unprotected: within a class, items sitting in different sub-classes are generally **not** considered similar goods. Ten items spread across ten sub-classes block far more than ten items crowded into one — which is why every result here shows its sub-class, and why the [class pages](index.md) are grouped that way too.

## Build the filing list here, not in a spreadsheet

**+** adds an item to the application list. The list groups by class, counts against the **10 items included** in the per-class fee, warns when a class goes over, and totals the fee as you go. **Copy list** gives a plain-text working list (Chinese wording, English, code, sub-class); **CSV** gives the same as a spreadsheet. The list stays in this browser, and **Clear** can be undone for a few seconds after you press it.

## What is behind this page

The search runs entirely client-side against a 2.2 MB index (about 580 KB compressed) built from the same catalogue as the [45 class pages](index.md) and the [CSV / JSON dataset](index.md). Matching is precision-first: a whole-word match is required, so "app" does not return every *apparatus*; if that finds nothing, the search falls back to word-prefix. The data is reviewed against the CNIPA classification — the current review date is on the [classification overview](index.md).
